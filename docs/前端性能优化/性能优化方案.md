# 前端性能优化方案

## 一、背景与问题

通过 Lighthouse（慢 4G 模拟）对 `/dashboard` 分析，发现以下性能问题：

| 问题 | Lighthouse 表现 | 根因 |
|------|----------------|------|
| 首次进入白屏 | FCP 3.9s / LCP 6.1s | JS 包过大 + 无首屏占位 |
| JS 包太大 | Reduce unused JS ~1.3MB | antd 全量引入 + 入口包过大 |
| HTTP 时长长 | HTTP/1.1，Est savings 940ms | 无 HTTPS，无法启用 HTTP/2 |
| 资源请求多 | 21 个 HTTP/1.1 请求 | vendors 未拆分、头像大图、favicon 404 |
| 头像浪费传输 | 460x460 显示 40x40 | GitHub 头像未加尺寸参数 |

优化目标：降低首屏传输量、消除白屏、合理分包。

## 二、优化前 vs 优化后

### 首屏传输量

| 资源 | 优化前（未压缩传输） | 优化后（gzip 传输） |
|------|------|------|
| antd-vendor | 923KB | 272KB gzip |
| react-vendor | 165KB | 51KB gzip |
| utils | 218KB | 26KB gzip |
| index | 159KB | 11KB gzip |
| **首屏合计** | **~1.4MB** | **~376KB gzip（↓73%）** |

## 三、已实施的优化

### 1. nginx 开启 Gzip 压缩

**文件**：`nginx.conf`

JS/CSS/JSON 传输体积减 60-70%，是首屏提速的最大单点优化。

```nginx
gzip on;
gzip_comp_level 6;
gzip_min_length 1k;
gzip_vary on;
gzip_types
    text/plain
    text/css
    application/json
    application/javascript
    text/javascript
    application/xml
    image/svg+xml
    font/ttf
    font/otf
    application/vnd.ms-fontobject;
```

### 2. Vite 函数式分包

**文件**：`web_front/vite.config.ts`

按依赖归属拆分 vendors，避免大而全的 chunk，利于浏览器长期缓存。

```ts
manualChunks(id) {
  if (!id.includes('node_modules')) return undefined;
  // antd 组件库 + 图标 + rc-* 依赖（先于 react 判断，避免误匹配）
  if (id.includes('/antd/') || id.includes('@ant-design') || id.includes('/rc-') || id.includes('@rc-component') || id.includes('/react-is/')) {
    return 'antd-vendor';
  }
  // react 全家桶 + 状态管理（精确路径匹配）
  if (id.includes('/react/') || id.includes('/react-dom/') || id.includes('/react-router') || id.includes('/scheduler/') || id.includes('/zustand/')) {
    return 'react-vendor';
  }
  // axios / dayjs
  if (id.includes('/axios/') || id.includes('/dayjs/')) {
    return 'http-utils';
  }
  // gsap 动画库（懒加载页面按需）
  if (id.includes('/gsap/')) {
    return 'gsap-vendor';
  }
  // 腾讯云 COS SDK（上传场景才用）
  if (id.includes('cos-js-sdk')) {
    return 'cos-vendor';
  }
  return 'vendor';
}
```

**注意**：分包规则必须用**精确路径匹配**（如 `/react/`），避免 `id.includes('react')` 误把 `@ant-design/react-slick` 等 antd 内部依赖归入 react-vendor，导致 react-vendor 膨胀到 900KB+。

### 3. DashboardLayout 懒加载

**文件**：`web_front/src/app/App.tsx`

后台布局（含 gsap 动画、antd 布局组件）改为 `lazy` + `Suspense`，不再进首屏入口包，登录后才加载。

```tsx
const DashboardLayout = lazy(() => import('@/components/layout/DashboardLayout'));

// 路由中使用 Suspense 包裹
<ProtectedRoute>
  <Suspense fallback={<Spin />}>
    <DashboardLayout />
  </Suspense>
</ProtectedRoute>
```

### 4. 首屏加载骨架屏

**文件**：`web_front/index.html`

index.html 内联 loading spinner + "加载中"提示，React 挂载前避免白屏，挂载后自动替换。

```html
<div id="root">
  <div id="app-loading">
    <div class="spinner"></div>
    <div class="loading-text">加载中...</div>
  </div>
</div>
```

### 5. GitHub 头像尺寸优化

**文件**：`web_front/src/store/index.ts`

GitHub 头像 URL 追加 `s=80` 参数，避免下载 460x460 大图（显示仅 40px）。

```ts
function optimizeAvatar(url?: string | null): string | undefined {
  if (!url) return undefined;
  if (url.includes('avatars.githubusercontent.com')) {
    return `${url}${url.includes('?') ? '&' : '?'}s=80`;
  }
  return url;
}
```

### 6. index.html SEO / 资源优化

**文件**：`web_front/index.html`

- 新增 `<meta name="description">`（提升 SEO 分）
- `<link rel="icon" href="data:,">` 避免 favicon 404 请求
- 移除错误指向 `http://localhost:8000` 的 `preconnect`（开发残留）

### 7. index.html 缓存策略

**文件**：`nginx.conf`

- `/`（index.html）：`Cache-Control: no-cache, must-revalidate`，每次校验最新版本
- `/assets/`（带 hash 构建产物）：`expires 1y; Cache-Control: public, immutable`，长期缓存

```nginx
location / {
    add_header Cache-Control "no-cache, must-revalidate";
}
location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

### 8. antd 按需改造（结论：无收益）

**文件**：21 个页面组件 `from 'antd'` → `from 'antd/es/xxx'`

将全量 `import { X } from 'antd'` 改为按需 `import X from 'antd/es/x'`。

**结论**：实测 antd-vendor 体积几乎无变化（880KB → 880KB）。原因：
- 项目使用了 20+ antd 组件，覆盖大部分模块
- antd v5 每个组件共享大量公共依赖（theme 系统、rc-*、_util 等），传递依赖几乎覆盖全部模块
- 这是 antd v5 架构决定的，与引入方式无关

**若需压缩 antd 体积，方向是减少使用的组件种类**，而非按需导入方式。

## 四、Lighthouse 分析结论与剩余瓶颈

### 剩余瓶颈：HTTP/1.1（无 HTTPS）

Lighthouse 明确提示 **"Modern HTTP: Est savings of 940ms"**。启用 HTTP/2 必须使用 HTTPS，当前 `http://xg-2.frp.one:31431` 是无 TLS 明文，浏览器强制 HTTP/1.1。

### 其他未决项（影响小）

| 项 | 影响 | 建议 |
|----|------|------|
| 图片懒加载 | 小 | 帖子列表图片可加 `loading="lazy"` |
| 可访问性 | 非性能 | 按钮缺 accessible name、图片缺 alt（已在 SEO 部分修复头像 alt） |
| CSP / HSTS | 安全 | 需 HTTPS 后配置 |

## 五、后续优化建议

1. **配置 HTTPS 启用 HTTP/2**（最大收益，预计省 ~940ms）：
   - frp 支持 TLS 时，前端地址改为 `https://`，nginx 加 `listen 5645 ssl http2;`
   - 需提供域名证书（frp 已绑域名时可用 Let's Encrypt）

2. **图片统一懒加载**：帖子/动态列表封面图加 `loading="lazy"`

3. **COS 图片压缩**：用户上传头像/帖子图展示时加 COS 图片处理参数（`imageMogr2/thumbnail`）

4. **服务端渲染或静态化**：若对 SEO/首屏有更高要求，可考虑 SSR（当前为纯 SPA）
