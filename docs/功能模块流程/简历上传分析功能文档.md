# AI 面试系统功能流程设计文档（最终版）

## 1. 系统整体设计

AI 面试系统拆分为两个核心业务模块：

1. **我的简历模块**

   * 用户简历上传
   * 简历文件管理
   * 简历 AI 分析

2. **AI 面试模块**

   * 创建面试任务
   * 加载获取简历分析数据
   * LangGraph Agent 面试流程
   * 回答分析
   * 能力评分
   * 面试报告生成

整体架构：

```
                         用户

                          |
          ┌───────────────┴───────────────┐

          ↓                               ↓

     简历管理模块                    AI面试模块

     上传简历                        上传简历
     简历管理                        创建面试
     分析结果                        获取分析结果


          └───────────────┬───────────────┘

                          ↓

                  Resume Service

                          ↓

              Resume Analysis Service

                          ↓

                 Interview Agent

```

# 2. 简历模块设计

## 2.1 简历上传流程

用户可以通过：

* 简历管理页面上传
* AI 面试页面上传

两个入口最终进入统一简历服务。

流程：

```
用户上传简历

        ↓

上传 COS 对象存储

        ↓

获取文件地址

        ↓

计算文件 Hash

        ↓

查询是否已有相同简历

        ↓

创建或复用 Resume

        ↓

进入简历分析流程

        ↓

页面展示 AI 分析等待状态

```

---

# 3. 简历唯一性设计

为了避免：

* 简历管理模块上传一次
* 面试模块再次上传同一份简历

系统使用文件 Hash 判断。

例如：

```
resume.pdf

        ↓

SHA256

        ↓

file_hash
```

数据库：

## Resume 表

```
id

user_id

file_url

file_name

file_hash

status

created_time

updated_time

```

唯一约束：

```
(user_id,file_hash)
```

保证：

同一个用户同一个文件只有一份简历记录。

# 7. 简历分析互斥锁

## 7.1 为什么需要锁

场景：

用户：

```
简历管理上传

        ↓

MQ分析任务执行


同时


进入面试

        ↓

再次上传同一简历

```

如果没有锁：

* 创建两个 AI 分析任务
* 重复消耗 Token
* 分析结果覆盖

---

## 7.2 Redis 分析锁

Key：

```
resume:analysis:lock:{resume_id}
```

Value：

```
task_uuid
```

获取：

```
SET key value NX EX 600
```

成功：

```
当前任务负责分析
```

失败：

```
已有分析任务执行
```

注意：

锁竞争用户无感知。

# 13. 面试执行锁

Redis：

```
interview:lock:{session_id}
```

作用：

防止：

```
浏览器A

执行面试


浏览器B

同时执行面试
```

避免：

* 问题状态冲突
* 重复评分
* LangGraph 状态污染

---

# 14. LangGraph 状态恢复

Redis：

```
interview:checkpoint:{session_id}
```

保存：

```json
{
 "node":"answer_analysis",
 "question_index":5,
 "status":"running"
}
```

异常恢复：

```
用户重新进入

        ↓

读取checkpoint

        ↓

恢复Graph状态

        ↓

继续执行

```

# 17. 核心设计原则

## 简历模块

负责：

* 简历资产管理
* 文件存储
* AI分析
* 分析结果维护

## 面试模块

负责：

* 面试流程
* Agent执行
* 问答分析
* 能力评分

## Redis

负责：

* 高频缓存
* 分布式锁
* 状态恢复

## MQ

负责：

* 异步分析
* 服务解耦
* 完成通知

## MySQL

负责：

* 最终数据存储
* 数据一致性保证

最终形成：

**多入口上传简历 → 统一简历服务 → MQ异步分析 → Redis锁保证唯一分析 → 分析完成通知 → Interview Agent消费分析结果 → LangGraph执行智能面试。**
