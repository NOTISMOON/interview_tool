# 面试模块重构方案

> 版本：v2.0
> 更新日期：2026-08-17
> 项目：AI 面试教练（interview_tool）

---

## 一、需求梳理

### 1.1 核心痛点（当前问题）
1. 简历上传后，题目生成完成前就展示了所有题目，面试者提前看到题目，缺乏真实面试感
2. 当前面试是"打字答题 + 固定时间倒计时"模式，不符合真实面试场景
3. 题目数量固定，无法根据回答质量动态追问
4. 缺少设备检测（麦克风/摄像头）环节

### 1.2 新需求总结

| 环节 | 需求 |
|------|------|
| 简历上传 | 上传后异步消费，生成面试题和面试者画像 |
| 题目生成 | 异步生成，不提前展示题目列表 |
| 设备检测 | 开始面试前检测麦克风、摄像头权限 |
| 答题方式 | **语音回答**为主，不依赖打字 |
| 每题流程 | 20 秒思考（前 10 秒锁定，后台分析追问+准备下一题）→ 作答 → 点击"完成回答"进入下一题 |
| 思考时间 | 20 秒，前 10 秒不可跳过（后台干活），后 10 秒可提前作答 |
| 题目数量 | **不固定**，由简历分析结果决定，包括基础题 + 追问 |
| 追问机制 | 后台在思考阶段自动判断追问，不展示"分析中"等中间状态，用户无感知 |
| 题目来源 | 简历分析后生成几个方面的基础问题（已分类），追问是动态追加的 |

```
│  1. 用户上传简历文件                                                   │
│  2. 后端保存文件 + 异步生成面试题和画像                                 │
│  3. 前端轮询简历状态 → 解析完成(status=ready) → 按钮变为"开始面试"      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘

┌─ 面试阶段 ──────────────────────────────────────────────────────────┐
│                                                                       │
│  1. 点击"开始面试" → 进入设备检测页                                    │
│  2. 检测麦克风/摄像头 → 通过后进入面试                                  │
│  3. 后端根据简历ID查询面试题和画像                                      │
│  4. 逐题消费：                                                        │
│     a. 前端展示题目 → 20秒思考倒计时                                   │
│     b. 前10秒锁定，后台做追问判断+生成下一题（用户无感知）               │

│     d. 20秒到 → 强制作答                                              │
│     e. 面试者点击"完成回答" → 音频发送后端 → 直接进入下一题思考          │
│     f. 若有追问，下一题即为追问（用户看到追问标签）                      │
│     g. 所有题目完成 → 生成报告 → 跳转报告页                            │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## 三、页面状态设计

### 3.1 面试主页面（InterviewPage）状态机

```
                    ┌──────────────┐
                    │  选择/上传简历 │
                    └──────┬───────┘
                           │ 点击"开始生成面试题"
                           ▼
                    ┌──────────────┐
                    │  分析中...    │ ← 轮询简历状态
                    │  (loading)   │
                    └──────┬───────┘
                           │ 简历分析完成
                           ▼
                    ┌──────────────┐
                    │  设备检测页    │ ← 检测麦克风/摄像头
                    └──────┬───────┘
                           │ 检测通过 → 点击"开始面试"
                           ▼
                    ┌──────────────┐
                    │  面试间       │ ← 跳转独立页面 InterviewSession
                    │  (逐题消费)   │
                    └──────┬───────┘
                           │ 所有题目完成
                           ▼
                    ┌──────────────┐
                    │  面试完成页    │ ← 面试间内展示
                    └──────────────┘
```

### 3.2 各状态详细说明

#### 状态 1：选择/上传简历
- 展示已有简历列表
- 支持上传新简历
- 选择简历后点击"开始生成面试题"

#### 状态 2：分析中（新增）
- 显示加载动画 + "AI 正在分析你的简历..."
- 轮询简历状态（每 2 秒查一次）
- 状态变为 ready 后自动进入设备检测
- **不展示任何题目信息**

#### 状态 3：设备检测页（新增）
- 麦克风权限检测 + 音量测试
- 摄像头权限检测 + 画面预览
- 两项都通过后，显示"开始面试"按钮

#### 状态 4：面试间（独立页面，跳转进入）
- 点击"开始面试"后，跳转至面试间独立页面
- 面试间顶部有退出按钮，退出时确认并返回主页面
- 逐题展示，不提前预览
- 每题流程：
  1. 展示题目 + 题目类型标签
  2. 20 秒思考倒计时（前 10 秒锁定，后台做追问判断+生成下一题）
  3. 后 10 秒可提前跳过，或 20 秒到后强制进入作答
  4. 开始录音作答
  5. 面试者点击"完成回答" → 直接进入下一题思考（无中间等待）

## 四、面试答题页详细设计

### 4.1 每题的两阶段

```
┌──────────────────────────────────────────────────────────────────┐
│  阶段 1: 思考阶段（20 秒，前 10 秒锁定）                            │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  📝 第 3 题 · 技术能力                                       │  │
│  │                                                            │  │
│  │  请描述你在项目中如何处理高并发场景？                           │  │
│  │                                                            │  │
│  │       ⏱ 思考时间  0:12    （10秒后可提前作答）                │  │
│  │       [ 0~10s: 请稍候... ]  [ 10~20s: 跳过思考，开始作答 ]    │  │
│  └────────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────────┤
│  阶段 2: 作答阶段（无固定时间限制）                                  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  🎤 正在录音中...                                            │  │
│  │                                                            │  │
│  │  ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░  (波形动画)                              │  │
│  │                                                            │  │
│  │  已录制 01:23                                               │  │
│  │                                                            │  │
│  │         [完成回答，进入下一题]                                 │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
注：回答完成后直接进入下一题的思考阶段，无中间等待状态。
    后台的追问判断和下一题生成都在思考阶段的前10秒内完成，用户无感知。
```

### 4.2 追问机制（后台透明）

```
答题流程:
  展示题目 → 思考(前10秒后台判断追问+生成下题) → 作答 → 完成回答
                                                          │
                                                          ▼
                                                    直接进入下一题思考
                                                    （如果后台判定有追问，下一题就是追问）
```

## 五、API 设计

### 5.1 简历相关

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/resume/upload` | 上传简历文件，返回简历ID，后台发MQ |
| GET | `/api/v1/resume/{id}/status` | 查询简历解析状态（前端轮询用） |
| GET | `/api/v1/resume/{id}/analysis` | 获取简历分析结果（分析维度，不包含具体题目） |

### 5.2 面试相关

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/interview/start` | 开始面试，传入简历ID，返回面试会话ID + 第一个题目 |
| GET | `/api/v1/interview/{session_id}/next-question` | 获取下一题（可能是追问） |
| POST | `/api/v1/interview/{session_id}/answer` | 提交音频回答（multipart/form-data） |
| GET | `/api/v1/interview/{session_id}/status` | 查询当前面试状态（当前题号、是否在等待追问判断等） |
| GET | `/api/v1/interview/{session_id}/report` | 获取面试报告 |

### 5.3 关键数据模型

```typescript
// 面试会话
interface InterviewSession {
  id: string;
  resumeId: string;
  status: 'waiting_device' | 'in_progress' | 'waiting_followup' | 'completed';
  currentQuestionIndex: number;
  totalBaseQuestions: number;  // 基础题数（不含追问）
  questions: InterviewQuestion[];  // 已展示的题目列表
  startTime: string;
}

// 面试题（扩展）
interface InterviewQuestion {
  id: string;
  questionNo: number;
  questionText: string;
  questionType: 'technical' | 'project' | 'behavioral';
  category: string;           // 所属维度：如"技术能力"、"项目经验"
  isFollowUp: boolean;        // 是否为追问
  followUpFromQuestionId?: string;  // 追问来源题目ID
  thinkingTime: number;       // 思考时间秒数（默认15）
  status: 'thinking' | 'answering' | 'submitted' | 'evaluated';
  userAudioUrl?: string;      // 用户回答音频URL
  transcription?: string;     // 语音转文字结果
  aiScore?: number;
  aiComment?: string;
}

// 简历分析结果
interface ResumeAnalysis {
  resumeId: string;
  status: 'parsing' | 'ready' | 'error';
  dimensions: AnalysisDimension[];  // 分析维度（不包含具体题目）
  candidateProfile: {
    name: string;
    yearsOfExperience: number;
    keySkills: string[];
    level: string;  // 初级/中级/高级
  };
}

// 分析维度
interface AnalysisDimension {
  name: string;         // 维度名称
  questionCount: number; // 该维度基础题数量
  icon: string;         // 图标标识
}
```

## 八、关键技术要点

### 8.1 语音采集
- 使用 Web Audio API + MediaRecorder API
- 录音格式：WebM/Opus 或 WAV
- 实时音量波形展示
- 需要在 HTTPS 环境下运行（getUserMedia 要求）

### 8.2 轮询策略
- 简历分析状态：每 2 秒轮询，最多 60 秒超时
- 追问判断状态：提交回答后轮询，每 1 秒，最多 10 秒
- 使用指数退避避免频繁请求

### 8.3 题目消费
- 前端只获取当前题目，不预加载后续题目
- 追问题目由后端动态追加到题目队列
- 前端通过 `next-question` 接口逐个获取

### 8.4 断线重连
- 面试过程中如果网络断开，记录当前进度
- 恢复后可从中断处继续
