# 文件上传功能文档（腾讯云 COS 前端直传 + 后端校验）

> 版本：v1.0
> 更新日期：2026-08-19
> 项目：AI 面试教练（interview_tool）

---

## 一、需求概述

### 1.1 背景

AI 面试教练平台需要支持用户上传简历文件（PDF、Word、图片等），用于简历解析和 AI 模拟面试。为减轻服务器带宽压力、提升上传体验，采用**前端直传腾讯云 COS + 后端校验**方案。

### 1.2 核心目标

| 目标 | 说明 | 优先级 |
|------|------|--------|
| 前端直传 COS | 文件不经过后端服务器，直接从浏览器上传到腾讯云 COS，减少服务器带宽消耗 | **必须** |
| STS 临时密钥 | 后端通过腾讯云 STS 服务生成临时访问凭证，前端凭临时密钥上传，避免暴露永久密钥 | **必须** |
| 后端上传校验 | 上传完成后前端回调后端，后端校验文件完整性、类型、大小，并记录上传记录 | **必须** |
| 文件类型限制 | 支持 PDF、Word（.doc/.docx）、图片（.png/.jpg/.jpeg），限制单文件最大 10MB | **必须** |
| 上传进度展示 | 前端展示上传进度条，支持取消上传 | **推荐** |
| 文件预览 | 上传完成后支持 COS 在线预览（图片直接展示，PDF/Word 通过 COS 文档预览） | **可选** |

### 1.3 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 对象存储 | 腾讯云 COS（Cloud Object Storage） | 高可用、低成本的对象存储服务 |
| 临时密钥 | 腾讯云 STS（Security Token Service） | 生成临时访问凭证，前端直传的安全基础 |
| 前端 SDK | `cos-js-sdk-v5` | 腾讯云官方 JavaScript SDK，支持分片上传、断点续传 |
| 后端 SDK | `tencentcloud-sdk-python`（已安装） | 调用 STS 服务生成临时密钥 |
| 后端框架 | FastAPI | 提供 STS 密钥接口 + 上传校验接口 |
| 缓存 | Redis | 缓存上传进度、临时状态 |

## 三、详细设计

### 3.1 STS 临时密钥申请（GET /api/v1/cos/sts-token）

#### 3.1.1 接口说明

前端在上传文件前，先向后端请求 STS 临时密钥和 COS 上传路径。后端根据用户身份和文件类型，生成限定权限的临时密钥。

#### 3.1.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file_name | string | 是 | 原始文件名（用于提取扩展名） |
| file_type | string | 是 | 文件用途：`resume`（简历）、`avatar`（头像） |
| file_size | integer | 是 | 文件大小（字节） |
| content_type | string | 是 | 文件 MIME 类型 |

#### 3.1.3 响应参数

```json
{
  "code": 0,
  "data": {
    "credentials": {
      "tmp_secret_id": "AKIDxxxxxxxxxxxxx",
      "tmp_secret_key": "xxxxxxxxxxxxx",
      "session_token": "xxxxxxxxxxxxx",
      "expired_time": 1766131200
    },
    "cos_key": "uploads/resumes/123/abc-def-123.pdf",
    "bucket": "interview-tool-1250000000",
    "region": "ap-guangzhou",
    "upload_url": "https://interview-tool-1250000000.cos.ap-guangzhou.myqcloud.com",
    "expire_time": 1800
  }
}
```

#### 3.1.4 STS 临时密钥权限策略（最小权限原则）

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "name/cos:PutObject",
        "name/cos:InitiateMultipartUpload",
        "name/cos:ListMultipartUploads",
        "name/cos:ListParts",
        "name/cos:UploadPart",
        "name/cos:CompleteMultipartUpload",
        "name/cos:AbortMultipartUpload"
      ],
      "resource": [
        "qcs::cos:ap-guangzhou:uid/1250000000:interview-tool-1250000000/uploads/resumes/123/*"
      ]
    }
  ]
}
```

> **安全要点**：STS 策略精确限定到 `{user_id}` 目录，用户只能上传到自己目录下，无法越权。

#### 3.1.5 后端校验逻辑

```
1. 校验用户已登录（JWT Token / Cookie）
2. 校验 file_type 是否为允许的类型（resume / avatar）
3. 校验文件扩展名是否在白名单内（.pdf / .doc / .docx / .png / .jpg / .jpeg）
4. 校验文件大小 ≤ 10MB（10 * 1024 * 1024 字节）
5. 生成 UUID 文件名，拼接 COS Key：uploads/{file_type}s/{user_id}/{uuid}.{ext}
6. 调用腾讯云 STS GetFederationToken API，传入限定策略
7. 返回临时密钥、COS Key、Bucket、Region
8. 在 Redis 中写入上传状态：upload:status:{cos_key} → {"status": "pending", "user_id": 123, "created_at": "..."}
   设置 TTL = 3600 秒（1 小时），超时未回调自动过期
```

### 3.2 前端直传 COS

#### 3.2.1 上传流程

前端使用 `cos-js-sdk-v5` 初始化 COS 实例，执行文件上传：

```typescript
// 伪代码：前端上传核心逻辑
import COS from 'cos-js-sdk-v5';

async function uploadFile(file: File) {
  // 1. 请求 STS 临时密钥
  const { data } = await api.getStsToken({
    file_name: file.name,
    file_type: 'resume',
    file_size: file.size,
    content_type: file.type,
  });

  const { credentials, cos_key, bucket, region } = data;

  // 2. 初始化 COS 实例
  const cos = new COS({
    getAuthorization: (_options, callback) => {
      callback({
        TmpSecretId: credentials.tmp_secret_id,
        TmpSecretKey: credentials.tmp_secret_key,
        SecurityToken: credentials.session_token,
        ExpiredTime: credentials.expired_time,
      });
    },
  });

  // 3. 执行上传（带进度回调）
  return new Promise((resolve, reject) => {
    cos.putObject({
      Bucket: bucket,
      Region: region,
      Key: cos_key,
      Body: file,
      onProgress: (progressData) => {
        // 更新进度条
        const percent = Math.round(progressData.percent * 100);
        updateProgress(percent);
      },
    }, (err, result) => {
      if (err) {
        reject(err);
        return;
      }
      // 4. 上传成功后回调后端
      api.uploadCallback({
        cos_key: cos_key,
        file_name: file.name,
        file_size: file.size,
        content_type: file.type,
        etag: result.ETag,
        location: result.Location,
      }).then(resolve).catch(reject);
    });
  });
}
```

#### 3.2.2 前端校验（上传前）

| 校验项 | 规则 | 错误提示 |
|--------|------|----------|
| 文件类型 | 仅允许 `.pdf` `.doc` `.docx` `.png` `.jpg` `.jpeg` | "仅支持 PDF、Word、图片格式" |
| 文件大小 | ≤ 10MB | "文件大小不能超过 10MB" |
| 文件数量 | 单次最多 1 个文件 | "一次只能上传一个文件" |

#### 3.2.3 上传进度展示

- 使用 `cos-js-sdk-v5` 的 `onProgress` 回调获取实时进度
- 前端展示进度条 + 百分比数字
- 支持取消上传：调用 `cos.cancelTask(taskId)`

### 3.3 后端上传回调校验（POST /api/v1/cos/callback）

#### 3.3.1 接口说明

前端直传 COS 成功后，回调后端接口通知上传完成。后端对上传结果进行二次校验，确保文件完整性和合法性。

#### 3.3.2 请求参数

```json
{
  "cos_key": "uploads/resumes/123/abc-def-123.pdf",
  "file_name": "我的简历.pdf",
  "file_size": 204800,
  "content_type": "application/pdf",
  "etag": "\"abc123def456\"",
  "location": "https://interview-tool-1250000000.cos.ap-guangzhou.myqcloud.com/uploads/resumes/123/abc-def-123.pdf"
}
```

#### 3.3.3 后端校验流程

```
1. JWT 认证 → 获取当前用户 user_id
2. 校验 cos_key 路径前缀是否匹配当前用户：
   uploads/{file_type}s/{user_id}/*（防止伪造回调）
3. 从 Redis 读取上传状态：upload:status:{cos_key}
   - 不存在 → 拒绝（可能是伪造回调或超时）
   - 存在 → 继续校验
4. 调用 COS HEAD Object API 校验文件：
   - Content-Length 是否与 file_size 一致
   - Content-Type 是否与 content_type 一致
   - ETag 是否匹配
5. 校验通过 → 写入 MySQL upload_records 表
6. 更新 Redis 状态：upload:status:{cos_key} → status: "completed"
7. 触发后续业务逻辑（如简历解析、AI 面试）
8. 返回 upload_id 和状态
```

#### 3.3.4 响应参数

```json
{
  "code": 0,
  "data": {
    "upload_id": 12345,
    "cos_key": "uploads/resumes/123/abc-def-123.pdf",
    "file_url": "https://interview-tool-1250000000.cos.ap-guangzhou.myqcloud.com/uploads/resumes/123/abc-def-123.pdf",
    "status": "completed",
    "created_at": "2026-08-19T10:30:00Z"
  }
}
```

## 四、数据模型

### 4.1 MySQL 表：upload_records

```sql
CREATE TABLE upload_records (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id         BIGINT UNSIGNED  NOT NULL COMMENT '上传用户ID',
    file_type       VARCHAR(20)      NOT NULL COMMENT '文件用途：resume/avatar',
    file_name       VARCHAR(255)     NOT NULL COMMENT '原始文件名',
    file_size       BIGINT UNSIGNED  NOT NULL COMMENT '文件大小（字节）',
    content_type    VARCHAR(100)     NOT NULL COMMENT 'MIME类型',
    cos_key         VARCHAR(500)     NOT NULL COMMENT 'COS对象Key',
    cos_url         VARCHAR(1000)    NOT NULL COMMENT 'COS访问URL',
    etag            VARCHAR(100)     NOT NULL COMMENT '文件ETag',
    status          VARCHAR(20)      NOT NULL DEFAULT 'pending' COMMENT '状态：pending/completed/failed',
    error_message   VARCHAR(500)     NULL     COMMENT '错误信息',
    created_at      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_user_type (user_id, file_type),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='文件上传记录表';
```

### 4.2 Redis 缓存键设计

| Key | 类型 | 内容 | TTL |
|-----|------|------|-----|
| `upload:status:{cos_key}` | Hash | `{status, user_id, file_name, file_size, created_at}` | 3600s |
| `upload:daily:{user_id}:{date}` | String（计数器） | 当日上传次数 | 86400s |

> **用途说明**：
> - `upload:status:{cos_key}`：记录上传中间状态，用于回调校验时防伪造
> - `upload:daily:{user_id}:{date}`：限制单用户每日上传次数（如 20 次/天），防滥用

## 八、安全设计

### 8.1 安全措施清单

| 安全措施 | 说明 |
|----------|------|
| STS 临时密钥 | 前端仅持有临时密钥（有效期 30 分钟），永久密钥仅在后端使用 |
| 最小权限策略 | STS 策略精确限定到 `{user_id}` 目录，仅授予 `PutObject` 相关权限 |
| 路径隔离 | 不同用户的文件存储在不同目录，COS Key 包含 `user_id` 前缀 |
| 后端回调校验 | 回调时校验 `cos_key` 路径前缀是否匹配当前用户，防伪造回调 |
| 文件类型白名单 | 前后端双重校验文件扩展名和 MIME 类型 |
| 文件大小限制 | 前后端双重校验文件大小 ≤ 10MB |
| 上传频率限制 | 单用户每日最多上传 20 次（Redis 计数器），防滥用 |
| COS 防盗链 | 配置 COS Referer 白名单，仅允许自己的域名访问 |
| 签名 URL | 敏感文件使用 COS 预签名 URL 访问，设置较短有效期 |

### 8.2 威胁模型与防护

| 威胁 | 防护措施 |
|------|----------|
| 前端伪造回调 | 回调时校验 cos_key 路径前缀 + Redis 状态 + COS HEAD Object 校验 |
| 越权上传到他人目录 | STS 策略限定 `user_id` 目录，临时密钥无法越权 |
| 上传恶意文件 | 文件类型白名单 + 后续可接入病毒扫描 |
| 上传超大文件消耗存储 | 前后端双重大小限制 10MB |
| 刷量上传 | 每日上传次数限制（Redis 计数器） |
| 永久密钥泄露 | 永久密钥仅在后端环境变量中使用，前端永远无法获取 |

## 九、错误处理

### 9.1 错误码定义

| 错误码 | HTTP 状态码 | 说明 |
|--------|-------------|------|
| `UPLOAD_FILE_TYPE_INVALID` | 400 | 文件类型不支持 |
| `UPLOAD_FILE_SIZE_EXCEED` | 400 | 文件大小超过限制 |
| `UPLOAD_DAILY_LIMIT` | 429 | 当日上传次数已达上限 |
| `UPLOAD_STS_ERROR` | 500 | 获取 STS 临时密钥失败 |
| `UPLOAD_CALLBACK_INVALID` | 400 | 回调参数无效（cos_key 不匹配） |
| `UPLOAD_NOT_FOUND` | 404 | 上传记录不存在 |
| `UPLOAD_COS_ERROR` | 502 | COS 服务异常 |
| `UPLOAD_FILE_NOT_FOUND` | 404 | COS 文件不存在（HEAD 校验失败） |

### 9.2 前端错误处理

```typescript
// 错误分类处理
const ERROR_HANDLERS: Record<string, () => void> = {
  UPLOAD_FILE_TYPE_INVALID: () => showToast('不支持的文件类型，请上传 PDF、Word 或图片'),
  UPLOAD_FILE_SIZE_EXCEED: () => showToast('文件大小超过 10MB 限制'),
  UPLOAD_DAILY_LIMIT: () => showToast('今日上传次数已用完，请明天再试'),
  UPLOAD_STS_ERROR: () => showToast('上传服务异常，请稍后重试'),
  // 网络错误
  NETWORK_ERROR: () => showToast('网络连接失败，请检查网络后重试'),
};
```
